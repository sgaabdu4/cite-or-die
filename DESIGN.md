# cite-or-die Design

## Overview

The browser workspace combines document upload, chat, and source evidence. The top bar exposes tenant, matter, authentication, and provider settings. The CLI supports the same ingest and chat flow. This inventory describes the existing interface; no visual change is proposed.

## Colors

[tokens.css](src/cite_or_die/ui/tokens.css) owns the palette, spacing, sizes, typography, and shadows. Keep its values and this file's front matter in sync.

Every text field, text area and select has a `field-line` outline at rest, and the Choose file drop zone and the Sources resize handle use the same colour. A focused field turns its border green and adds the focus ring. `field-line` measures at least 3:1 against white, paper, the composer surface, the switcher surface and the upload surface, which are the surfaces a field sits on (WCAG 1.4.11). The app has one light theme (`color-scheme: light`) and no dark theme, so `field-line` has one value. A dark theme needs its own `field-line` that meets the same 3:1 against the dark surfaces.

## Typography

Use the interface stack for body text and controls, the heading stack for page and section titles, and the source stack for line-numbered excerpts.

## Layout

The shell uses a top bar above the workspace. Workspace controls wrap. Dialog and pane layouts adapt at their existing media query breakpoints. Media queries use literal thresholds because CSS does not accept custom properties in query conditions.

## Components

[UI-LIBRARY.md](UI-LIBRARY.md) lists the shared browser components. The library also holds the native markup for the workspace controls, dialogs, source panel, composer, and citation viewer.

- Atoms: labelled inputs, action buttons, citation chips, status labels, and source text.
- Molecules: tenant/matter controls, provider status, upload controls, and citation references.
- Organisms: workspace setup dialog, provider settings dialog, chat panel, and source reader.
- Template and page: the single workspace in [index.html](src/cite_or_die/ui/index.html), including loading, empty, error, and evidence states.

## Do's and Don'ts

Keep source evidence tied to the active tenant and matter. Preserve visible focus states, labelled dialogs, disabled loading controls, and explicit provider privacy guidance. Provider keys must never return to the browser after storage.
