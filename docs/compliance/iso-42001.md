# ISO 42001 Alignment

cite-or-die is designed for customer-controlled deployment.

- Governance: release artifacts include tests, eval gates, a dependency CVE scan, SBOM generation, diligence E2E evidence, and security/adversarial workflows.
- Data controls: documents and diligence objects remain inside the deployment boundary; audit payloads use allowlisted fields.
- Monitoring: OpenTelemetry, Prometheus, Loki, Tempo, and Grafana run in the compose stack.
- Risk management: prompt injection, retrieved-content injection, PII redaction, citation faithfulness, diligence isolation, and expected-risk gates are tested.
- Human oversight: generated diligence report drafts default to `needs_review` and are not final sign-off.
- Change control: phase tags and release checks tie code, package version, and Docker image version together.

This document is an implementation alignment note, not a certification claim.
